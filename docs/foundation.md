## 플레이 흐름

타이틀 → 부임 준비 → 사업 지도·집무실 → 인물 선택과 보고 → 생산·소재·거래처·재무 장부 → 금월 결재 → 소재 발주 → 월 결산 → 자동 저장.

사업 지도에서 공장·소재 야드·수입 항만·거래처·법인 사무동을 선택하면 각 공간의 그림과 담당자 보고를 주 화면에 표시한다. 「사업 지도로」는 방금 방문한 거점으로 초점을 돌린다. 숫자는 상단 상태줄과 선택한 거점·명령에 필요한 정보로 표시한다. 긴 표와 인수 보고는 닫을 수 있는 보조 창에서 읽는다. 장부를 닫으면 방문 중인 공간을 유지하며, 기존 안건의 선택 순서와 계산은 그대로 사용한다.

## 저장 보존

별도 localStorage 키를 사용하고 새 게임 시작·월 결산 완료에 자동 저장한다. 결재 중 변경은 저장하지 않아 새로고침 후 월초 checkpoint가 유지된다. bigPlan은 사건 ID로 직렬화하고 로드 시 원본 덱의 함수에 다시 연결한다. 여신 확대·공급업체 감사·안전사고 예약은 타입 메타데이터로 복원하여 원본과 같은 효과를 적용한다. 알 수 없는 예약 효과나 잘못된 저장은 기존 checkpoint를 덮어쓰지 않는다.

원본 저장은 예약 효과 정보가 이미 누락될 수 있어 자동 가져오기를 제공하지 않는다. 브라우저 저장이 차단되거나 삭제되면 복원이 불가능하다. 서버 계정·클라우드 저장은 이 기반에 포함하지 않는다.

## 실행과 산출물

Node22+, 추가 의존성 없이 npm run dev / npm test / npm run build. 새 빌드는 dist/, 원본 단일 HTML은 기존 경로를 유지한다. 개발 중에는 service worker를 등록하지 않아 오래된 캐시가 수정 내용을 가리지 않게 한다. 배포 빌드의 service worker는 자기 캐시 이름만 정리한다. 배포·푸시·커밋은 수행하지 않는다.

새 그림은 art/strategy-*와 docs/media-production.md에 출처·프롬프트를 남긴다. 글자와 명령은 그림에 넣지 않고 실제 HTML로 구현한다. 창작 BGM 6곡·징글 3개·효과음 12개는 `music/` 원본에서 `audio/`로 생성한다. `npm run audio:render`와 `npm run audio:verify`로 재현·검사한다. 21개 WAV 합계는 약 49.78MiB다. 전체48개월 수동 밸런스 검증은 별도 작업이다.

## 음향 경계

`CCAudio`는 G와 경제 RNG를 읽거나 바꾸지 않는다. 설정은 게임 checkpoint와 별도인 `coilcenter:audio:v1`에 보관한다. 사용자 입력 전에는 컨텍스트나 음원 요청을 만들지 않는다. 동일 장면은 유지하고 음악 전환은 0.75초, 징글 중 배경 음악은 30%, 종료 후 0.6초 복원한다. 징글이 겹치면 한 징글의 믹스 예산을 나눠 쓴다. BGM 디코드 캐시는 최대 세 곡이며 숨김 때 짧은 소리를 버리고 재개 거절은 사용자 재시도로 복구한다.

배포 서비스워커는 음악을 필수 설치 목록에 넣지 않는다. 요청해서 받은 manifest/WAV만 같은 버전 캐시에 보관한다. 미캐시 곡의 오프라인 실패는 무음으로 처리하고 게임 shell 설치·진행을 막지 않는다. 코드·CSS·그림·manifest·WAV 바이트가 캐시 버전에 반영된다. 개발 서버는 WAV MIME과 음원 변경 감시를 제공한다.

월간·분기 실제 결재와 자동 저장을 음소거/정상/오류 오디오로 비교하는 회귀 검사는 `tests/audio-integration.test.mjs`다. 실제 브라우저, 물리 iOS, 사람의 청취는 VM 회귀와 별도로 [오디오 검증 기록](audio-verification.md)에 남긴다.
