# 첫 분기 안내 계약

새 게임의 기존 생성·월초 저장이 끝나면 한 번 직원 인수인계를 연다. 닫기·Escape로 즉시 게임에 돌아갈 수 있다. 게임 메뉴의 **취임 안내 → 직원 인수인계 다시 보기**는 모든 재임 월에 열 수 있다. 이어하기·장면 전환·결산 뒤 렌더는 인수인계를 자동으로 열지 않는다. 타이틀 취임 안내는 게임 상태 없이도 원작 크레딧과 설명을 표시한다.

| 재임 | 담당자의 확인 목표 | 직접 행동 |
| --- | --- | --- |
| 1개월 | 확정 수주와 발주 전 재고·미착·생산 중 소재 확인 | 정 영업 보고, 재고·입항 장부 |
| 2개월 | 첫 결산 뒤 이익·현금·채권·차입 차이 확인 | 한 재무 보고, 경영 장부 |
| 3개월 | 다음 분기의 생산 부하와 정비 상태 확인 | 구 공장 보고, 생산 현황 |
| 4개월 | 보고 → 장부 → 결재 순서만 짧게 상기 | 기존 게임 명령 사용 |
| 5개월 이후 | 첫 분기 안내 블록 종료, 이후에는 진행 상황 안내와 취임 안내 유지 | 기존 게임 명령 사용 |

분기 모드(`G.mpt === 3`)는 첫 턴에 세 달의 확인 관점을 함께 보여 준다. 첫 결재가 세 달을 집행하고 다음 화면이 4개월차임을 명시한다. 목표는 읽기 전용 권고이며 완료 체크·강제 순서·추가 보상은 없다.

`src/ui/onboarding.js`는 `G.s.turn`과 `G.mpt`만으로 안내 단계를 정한다. `G`, 저장 schema, 엔진 RNG를 바꾸지 않으며 `dealTurn`이나 `briefing`을 호출하지 않는다. 직원 행동은 이미 화면에서 공유하는 보고 캐시와 `ccShowReport`를 사용한다. 장부 행동은 기존 `ccOpenDossier`를 사용한다. 인수인계 역시 같은 native dialog의 제목 초점·Escape·닫기·호출자 초점 복귀를 사용하며 열린 dialog와 겹치지 않는다.

검증 명령: `node --test tests/onboarding.test.mjs tests/setup.test.mjs tests/save.test.mjs tests/audio-integration.test.mjs`.

브라우저 확인 지점: `#cc-help`, `#cc-reopen-handover`, `.cc-dossier-close`, `#cc-quarter-guidance[data-guidance-stage]`, `[data-guidance="report"]`, `[data-guidance="ledger"]`, `#go`. 단계 값은 `month-1`, `month-2`, `month-3`, `quarter`, `independent`이다. VM은 행동 연결·상태 불변·저장·전환을 검증하며 실제 키보드 Escape와 1440×1000/390×844 화면 배치는 별도 브라우저 QA 대상이다.

## 결재·결산 설명

결재 설명은 선택지의 원문 `fx`를 보존하면서 비용·효과·위험을 읽기 전용으로 분류한다. 지급 시점은 실제 동작을 확인한 카드에만 명시한다. 설명을 만들면서 `apply`를 미리 실행하거나 게임 RNG를 소비하지 않는다.

결산의 「영업이익은 왜 달라졌나」는 `prelude + history`에서 이번 결산의 실제 개월 수(`R.months || 1`)를 제외하고 같은 길이의 직전 기간과 비교한다. `영업이익 = 매출총이익 − 고정비 − 변동비 − 감가상각 + 사건 영업 조정`의 큰 증감 세 항목과 나머지를 보여 주며, 센트 반올림 차이는 나머지에 포함해 표시 합계를 맞춘다. 이자·대손·금융비용은 제외하고 개별 결재의 효과로 단정하지 않는다. 옛 보고의 항등식 비교에서는 누락된 영업 조정을 0으로 계산하되, 사건 상세 기록이 없다는 사실과 구분한다. 기간·수치가 누락되거나 원장이 맞지 않으면 비교 불가 이유를 표시한다.

외부창고비는 해당 기간의 실제 월별 `overTons × WAREHOUSE_OVER_COST`를 합산한다. 분기 집행이 중도 종료되면 실제 1~2개월만 사용한다. 이 안내 UI를 처음 도입한 작업은 `mergeReports`와 저장 보고서의 스키마·금액·월말 재고를 변경하지 않았다. 2026-10-24 경영 정합성 작업에서는 선택 필드 `finance`, `fulfillment`, `hqWatch`를 추가했다. 분기 보고는 실제 월의 흐름을 합산하고 잔액은 마지막 실제 월의 `bs`를 유지한다. 기존 큰 장부 항목, 손익 상세, 기간 사건과 결산 음향 연결을 유지한다.

검증 명령: `node --test tests/decision-explainer.test.mjs tests/settlement-guide.test.mjs tests/rules.test.mjs tests/save.test.mjs tests/audio-integration.test.mjs`.

결산 브라우저 확인 지점: `.cc-settlement-guide[data-settlement]`, `[data-contribution]`, `.cc-settlement-total`, `.cc-settlement-items`, `dialog #close`. 월·분기·부분 기간, 비교 불가, 기존 상세 펼침과 닫기 뒤 음악 복귀를 확인한다. 새 비교는 순수 읽기 함수이며 경제·저장·난수 불변은 고정 실제 엔진 보고서와 기존 오디오 통합 checksum으로 검증한다.

2026-10-24의 선택 설명은 요청 변화와 상한 적용 후 실제 변화를 구분한다. 본사 신뢰 99에서 +12를 요청했으면 실제 +1이다. 발주는 기준 권장 → 정책 배수 → 상한·최소선 적용 → 직접 확정값 순서로 설명한다. 결산의 접는 계산 근거에는 사건 영업 조정·금융비용·자산 거래와 납품 이행에 따른 본사 신뢰 회복을 표시한다. 직접 변화 관측은 런타임 전용이므로 재로드 뒤 관측이 없으면 0이라고 추정하지 않는다. [경영 규칙](management-rules.md)과 [저장 계약](save-contract.md)을 함께 따른다.
