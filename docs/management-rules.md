## 현금과 손익은 별도로 읽는다

사건 정비·품질·영업·복리·보험·세무·프로젝트 시작비는 해당 월의 영업 조정으로 반영한다. LC·채권 할인 수수료와 예약 credit 손실은 금융비용이다. 재고 매각은 실제 장부원가와 회수액의 차이만 손익이다. 채권 회수 원금·차입 원금·상환 원금과 자산 취득액은 그대로 이익이나 비용이 되지 않는다.

- 영업이익(OP) = 매출총이익 − 고정비 − 변동비 − 감가상각 + `finance.operatingAdjustment`.
- 순이익(NP) = 영업이익 − 이자 − 대손 − `finance.financeCost`.
- `operatingAdjustment = ΣoperatingDelta`, `financeCost = −ΣfinancialDelta`.

거래의 `amount`는 기준 금액이며 현금흐름이 아니다. `operatingDelta`는 OP에 더할 부호 있는 금액, `financialDelta`는 NP에 더할 금융손익이다. 현금은 거래 시 한 번 바뀌고 월말에는 pending의 손익을 소비한다. 표시용 `impacts`를 실제 원장으로 사용하지 않는다. 예약 credit 손실은 기존 현금 $980,000 감소를 금융손실로 기록하며 별도 매출채권 원금을 다시 줄이지 않는다.

태양광 자체 설치는 즉시 자산 취득·현금 지출 후 당월부터 상각·절감한다. 설치 큐나 3개월 지연은 없다. 옛 저장의 이미 설치된 태양광은 소급 자산화하지 않는다. `extraFixed`의 진짜 월 고정비·절감은 매월 반복한다. 일회 투자 비용과 혼동하지 않는다.

현금 프로젝트의 실제 비용·회수는 손익·현금·자기자본·한도 잔액을 닫기 전에 적용한다. 분기는 실행한 월의 손익·거래만 합산하고 잔액은 마지막 실제 월을 쓴다. 중도 종료로 1~2개월만 실행했으면 그 기간만 보고하며 임기 48개월 뒤 추가 결산은 없다.

## 날짜·신뢰·고객을 구별한다

turn 1은 2026년 1월, turn 12는 12월, turn 13은 다음 해 1월이다. 본사 연간 평가는 완료한 월 `R.turn` 12·24·36·48에 실행한다. 다음 의사결정 월 `s.turn`과 섞지 않는다. 새해 1월의 아직 없는 진도는 `null`이며 전년도 진도를 재사용하지 않는다. 이미 같은 연차 `W.hq.log.year`가 있으면 다시 보상하지 않는다.

납품 신뢰 회복의 분모는 판매 희망량에 의해 축소되기 전의 실제 자동차 내시, 분자는 실제 자동차 출하다. 판매 희망 0으로 분모를 없애 회복을 얻을 수 없고, 실제 수요 0이면 비율은 `null`·회복은 0이다. `s.running`이 참이거나 `turn > LEAD_TURNS + PREMIUM.leadAdd`인 월만 회복 대상이다. 초기 가동 준비 기간에는 자동 회복하지 않는다. 95% 경계는 계산 오차 1e-9를 허용하며 결과의 `trustRecovery`는 상한 적용 후 실제 증가량이다.

본사 신뢰 +12와 고객 관계 +8은 서로 다른 변화다. 예를 들어 신뢰 99에서 +12 요청은 실제 +1이다. 화재 지원 대상은 실제 노출 때 한 번 고정하며 카드 이름·결과·기억이 같은 고객을 가리킨다. 기억은 지원 한 번에 한 건, 저장 `bigPlan`은 기존 카드 ID를 유지한다. 대상 선택에 난수를 추가하지 않는다.

본사 감시는 `W.hqWatch`가 켜진 뒤 실제 결산 월마다 `R.hqWatch`를 남긴다. 부족 조건은 `cash < 0 || debt > debtLimit`이고 전월이 연속하지 않으면 delta는 `null`이다. 분기·부분 분기는 실제 월만 표시하며 감시 때문에 추가 결재나 자동 벌점을 만들지 않는다.

## 발주 약속과 확정 수량

발주는 최신 상태에서 기준 권장량 → 정책 배수 → 상한·최소선 적용 후 권장량을 계산한다. 고객별 사용량·기존 미착·야드와 자금 제약 때문에 1.7배 정책을 택해도 최종 권장량은 같을 수 있다. `capBy` 설명은 실제 제한을 보여 준다. 연간 본사 목표 수용은 약속이며 자동 발주·즉시 입고가 아니다. 목표 잔량과 남은 달의 단순 진도를 실제 입고 예상으로 읽지 않는다.

직접 확정한 유효 수량에 정책 배수나 권장량의 50톤 반올림을 다시 적용하지 않는다. 0톤·16.25톤도 보존한다. 분기 총 16.25톤의 현재 월별 배분은 `[0, 0, 16.25]`이며 합계가 보존된다. 마지막 발주 화면을 열 때 앞선 선택이 반영된 최신 한도를 다시 계산하고, 제출 시 그 한도로 검사한다. 고객별 합계와 월별 합계가 확정 총량과 일치하도록 집행한다. 임기 마지막 분기는 실제 남은 달만 계산한다. 구현은 [ui.js](../ui.js)의 `orderMonths`, `orderMonthlyPlan`, `orderRows`, `orderCard`, `buildDecision`, 검사는 [발주 정합성](../tests/order-integrity.test.mjs)을 따른다.

## 안전·사기·품질의 적용 시점

사고 확률은 원본 예약과 저장 복원 예약 모두 다음 공통 함수를 사용한다.

```text
base = clamp(0.3 + fatigue / 250, 0, 1)
factor = 0.5 + 0.25 × clamp(safety ?? 2, 0, 2)
probability = base × factor
```

전면 교체는 safety=0, 부분 교체는 `min(1,max(0,safety??2))`, 연기는 기존 safety(누락이면 0)에 +2다. 피로 50에서 safety 2/1/0의 확률은 0.5/0.375/0.25다. 전면 교체 상태에서 부분 교체해도 0을 유지한다. 누락된 옛 safety는 확률 계산에서 2로 읽지만 저장값을 억지로 초기화하지 않는다. 연기 예약은 2~5개월 뒤 현재 상태로 판정한다. 교체해도 삭제하지 않으며 기존 난수 호출 수를 유지한다. 사고가 나면 $260,000 현금 지출·영업비용, 사기 −12, 생산능력 배수 ×0.9가 남는다.

낮은 사기는 현재 가공 수율에 영향을 준다. 엔진의 사기 62 방향 0.08 평균회귀와 세계 월말의 낮은 피로에서 사기 58 방향 0.05 추가 평균회귀는 둘 다 유지한다. 월말 피로가 40을 넘으면 사기가 추가 감소하며, 품질은 `48 + equip×0.3 + morale×0.15 − fatigue×0.18 + qBoost` 목표로 차이의 0.22만큼 움직인다. qBoost는 매월 2 감소한다.

품질 원인 분석은 $55,000 비용과 별도로 현재 결재 기간의 무상 수율 보정 0.0022(0.22%p), 월말 품질 개선 요인 +14를 적용한다. 월말 품질은 같은 월의 클레임 위험 판정과 다음 월 수율에 영향을 준다. 품질 지수 환산 `94 + quality×0.05`를 실제 제품 로트 수율과 같다고 쓰지 않는다. 개별 요청 변화·즉시 실제 변화·환경이 반영된 월말 상태를 따로 읽는다.

## 기존 기록과 표시의 한계

v1의 새 필드는 선택값이다. 읽기·재저장만으로 과거 history/prelude의 비용·태양광 자산·연간 평가를 재작성하지 않는다. 다음 실제 결산에서 비차단 새 규칙 안내를 기록하고 `W.managementRulesVersion=1`로 반복을 막는다. 기존 primary·backup·결재 중 저장 거절과 원본 키 보호는 유지한다.

결재 직후의 실제 변화 관측은 런타임 전용이며 과거 보고서에 저장하지 않는다. 재로드 후 세부 기록이 없으면 ‘세부 미기록’으로 표시한다. 비교 계산에서 옛 `finance` 누락을 0으로 읽는 호환 처리는 과거에 사건 비용이 없었다는 증명이 아니다. 현재 최종 자동 검사·캠페인 결과와 별도 브라우저 QA 상태는 [날짜별 검증 기록](verification.md)으로 확인한다. 배포 완료·물리 iOS 검증·사람의 청취·아트 이용 권리는 이 문서가 보증하지 않는다.
