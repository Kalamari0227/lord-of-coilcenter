## 새 전략 경영 게임 기반

기존 48개월 경영 계산·인물·사건 위에, Renaissance를 참고한 고전 전략 게임 화면을 연결하고 있습니다.
타이틀에서 시작해 사업 지도와 집무실을 오가며 인물 보고·장부·명령을 확인하고 월간 결재를 진행합니다.

Node.js 22 이상에서 별도 패키지 설치 없이 실행합니다.

```sh
npm run dev
```

기존 `dist/`에 빌드 소유 표시가 없으면 안전을 위해 빌드가 거절됩니다. 실행 중인 개발 서버를 정리한 뒤 기존 폴더를 별도로 백업하고 빈 출력 위치를 사용하세요. 공유 실행 환경에서는 [격리 빌드 명령](docs/release-checklist.md)을 사용하세요.

개발 주소는 `http://127.0.0.1:4186`입니다. 파일 변경 후 브라우저를 새로고침하면 적용됩니다.
포트 변경은 `PORT=4190 npm run dev`처럼 지정합니다.

```sh
npm test       # 경제·저장·오디오·빌드 회귀 검증
npm run build # 분리형 게임을 dist/에 생성
```

새 화면은 `dist/index.html`과 동봉된 파일을 함께 제공합니다. 아래의 원본 단일 파일 `index.html`과 `build.sh`는 기존 배포 경로입니다.
새 게임의 저장은 `coilcenter:foundation:v1` 키를 사용합니다. 원본 저장을 덮어쓰거나 자동으로 변환하지 않습니다.
구조·범위는 [기반 설계](docs/foundation.md), 시각 기준은 [DESIGN.md](DESIGN.md), 실행 확인은 [검증 기록](docs/verification.md)을 참고하십시오.

## 음악과 효과음

FM 신스와 작은 오케스트라의 창작 배경 음악 6곡, 결산·종료 징글 3개, 효과음 12개를 포함합니다. 21개 WAV는 22,050Hz·16bit·stereo, 합계 약 49.78MiB입니다. 첫 화면은 조용히 열리고, 「음악 켜기」 또는 실제 새 게임·이어하기 입력으로 재생을 시작합니다.

타이틀·게임 메뉴·종료 화면의 「음향 설정」에서 전체·배경 음악·효과음 음량과 전체 음소거를 조절하고 여섯 곡을 미리 들을 수 있습니다. 설정은 `coilcenter:audio:v1`에 별도로 저장합니다. 미리듣기 창을 닫으면 원래 장면의 음악과 위치로 돌아갑니다. 소리가 차단되면 「음악 재개」로 다시 시도할 수 있습니다.

음원은 필요한 파일만 가져옵니다. 배포판에서 한 번 가져온 음원은 선택적으로 캐시하며, 오프라인에서 아직 받지 않은 곡은 조용히 실패해도 게임 진행과 저장은 계속됩니다. 오디오 파일 전체를 앱 설치 때 미리 받지는 않습니다.

```sh
npm run audio:render  # 악보·합성 원본에서 21개 음원 재생성
npm run audio:verify  # 파일·해시·루프·신호·크기 검사
npm run check         # 음원 검사, 회귀 테스트, 배포 빌드
```

제작·재현은 [오디오 제작 기록](docs/audio-production.md), 기술 검증과 실제 청취의 구분은 [오디오 검증 기록](docs/audio-verification.md)을 참고하십시오. 헤드폰·작은 스피커 청취와 물리 iOS 검증은 아직 UNVERIFIED입니다.

- **휴대폰에 앱으로:** 타이틀·게임 메뉴의 「설치 · 업데이트」에서 설치 안내를 확인합니다.
  안드로이드·PC는 설치 버튼이 나타나면 누르거나 브라우저의 앱 설치 메뉴를 사용합니다.

- **오프라인:** 온라인에서 게임 파일 저장이 끝난 뒤 사용할 수 있습니다. 음악·효과음은 이미 내려받은 음원만 재생합니다.
  브라우저가 사이트 저장 공간을 비웠다면 다시 온라인으로 열어야 합니다. 개발 미리보기는 오프라인 실행을 지원하지 않습니다.
- **로컬에서:** 저장소를 내려받아 `npm run dev`로 실행합니다. 현재 게임은 `dist/` 전체가 필요하며, 루트의 단일 `index.html`은 예전 버전입니다.

## GitHub Pages 배포

공식 주소는 `https://kalamari0227.github.io/lord-of-coilcenter/`입니다.
저장소 Settings → Pages의 Source는 **GitHub Actions**를 사용합니다.
`main`에 변경을 올리면 [배포 워크플로](.github/workflows/pages.yml)가 Node.js 22에서 음원 검사·테스트·빌드를 실행한 뒤 `dist/`만 배포합니다.
검사가 실패하면 새 버전은 배포하지 않습니다. Actions의 **Deploy game to GitHub Pages**에서 수동 재배포도 가능합니다.

이미지·음원·manifest·서비스워커는 상대 경로를 사용하므로 `/lord-of-coilcenter/` 아래에서 실행됩니다.
새 버전은 「설치 · 업데이트」에서 「기록 확인 후 새 버전 적용」으로 적용합니다. 결재 중이거나 저장이 실패하면 적용하지 않습니다. 「닫기 · 나중에 적용」으로 미룰 수 있고 다른 탭은 자동 새로고침하지 않습니다.
설치와 저장은 기기·브라우저별이며, 로컬 개발 주소의 저장은 배포 주소로 자동 이동하지 않습니다.

배포 방식은 [GitHub Pages 사용자 지정 워크플로 안내](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)를 따릅니다.

## 저장과 기록

「저장 관리」는 타이틀·게임 메뉴에서 열 수 있습니다. 자동 저장은 새 게임 직후, 결재 시작 전, 결산 뒤에 실행됩니다. 「저장 · 타이틀」은 저장 성공을 확인한 뒤 타이틀로 돌아갑니다.

- 마지막 확인 기록의 회사·연월·시각을 확인하고 JSON으로 내보내세요. 부분 결재 중 내보내기는 진행 중 선택을 제외한 이전 확정 기록입니다. 새로고침하면 마지막 확인 기록으로 돌아갑니다.
- 손상된 기록은 덮어쓰지 않습니다. 「이전 정상본 복구」 또는 저장 파일 가져오기에서 미리보기를 확인한 뒤 확정하세요. 정상 저장이 교체될 때 이전 정상본 한 개가 보존되므로 중요한 기록은 파일로 따로 보관하세요.
- 다른 탭 충돌은 작업을 확인한 뒤 최신 기록을 다시 읽어 해결합니다. 동시에 여러 탭에서 결재하지 마세요. 파일 형식·버전이 지원되지 않으면 가져오기를 거절합니다.
- 안전한 탭 간 잠금(Web Locks)을 사용할 수 없는 환경은 메모리에서만 진행합니다. 창을 닫으면 사라질 수 있으므로 확인된 기록을 내보내세요. 잠금을 지원해도 저장소 읽기·쓰기에 실패하면 새 게임이나 결재 진행이 거절될 수 있습니다. 실패 안내를 확인하고 저장 관리에서 재확인·복구하세요.
- 명예의 전당에는 완료한 게임의 회사·난이도·등급·모법이익·경영 스타일이 최대 50판 남고 CSV로 내보낼 수 있습니다.
- 계정·서버 동기화는 없습니다. 브라우저 데이터 삭제는 저장을 잃게 할 수 있습니다. 원본 `coilcenter.save.v1`과 현재 `coilcenter:foundation:v1`은 별개이며 자동 변환하지 않습니다.

세부 계약은 [저장 형식·복구 규칙](docs/save-contract.md)을 참고하세요.

## 시작할 때 고르는 것

**난이도**

| | 노멀 | 하드 |
|---|---|---|
| 자본금 | $35M | $25M |
| 은행 이자 | 연 3% | 연 5% |
| 인수 시점 차입금 | $20M 안팎 | $30M 안팎 |
| 물려받은 판매 기반 | 10.0% | 7.5% |
| 전임자가 남긴 장기재고 | 2,400t | 10,000t |
| **모법이익** 목표 | $45M | $58M |

자본금은 운전자본에서 역산했습니다. 순운전자본이 $23~32M이고 토지·건물·설비가 $20M이니
굴리는 돈은 $43~52M입니다. 그중 절반 남짓만 자본금이고 나머지는 은행 돈입니다 — 실제
코일센터의 자본 구조가 그렇습니다. 가공마진이 톤당 $40인 장사라 이자가 곧바로 적자로
이어집니다. 그게 이 게임의 압력입니다.

하드는 첫 1년을 버티는 것부터 일입니다. 목표가 올라가 S등급은 거의 안 나옵니다.

> **모법이익** = 모사(본사 철강사)가 우리에게 소재를 팔아 번 돈 + 법인(코일센터)의 영업이익.
> 본사가 이 법인을 세운 이유가 이 숫자입니다. 법인 혼자 잘 버는 것과는 다릅니다 —
> 일반재를 늘려 법인 손익만 챙기면 모사 몫은 한 푼도 안 늘고, 등급은 「혼자만 이겼습니다」가 됩니다.

**결재 주기**

| | 노멀 | 속성 |
|---|---|---|
| 기간 | 48개월 | 16분기 |
| 결재 | 48번 | 16번 |
| 한 번 결재하면 | 한 달 | 석 달 |

속성은 카드 한 벌로 석 달을 돌립니다. 적어낸 발주 톤수는 **석 달치**이고 세 달에 나눠 집행됩니다.
증설·본사 지시 수용은 분기 첫 달에만 집행됩니다. 한 번에 석 달을 돌리는 만큼
안건도 그만큼 더 올라옵니다(최대 7건 + 발주).

## 부임 — 돌고 있던 회사를 넘겨받는다
2026년 1월, 이미 운영 중인 코일센터에 사장으로 부임합니다. 게임을 시작하면 전임 사장이
굴린 16개월을 엔진이 실제로 돌리고, 그 마지막 12개월을 **작년 실적**으로 넘겨줍니다.
그래서 첫 달부터 창고에 소재와 가공제품이 있고, 바다 위와 본사 공장에 물량이 있고,
받을 돈과 은행 빚이 있습니다.

첫 화면에서 관리부장이 작년 실적을 브리핑하고, 실적표는 **지난달 · 작년 월평균 · 작년 연간**을
보여줍니다. 두 번째 달부터는 **당월 · 부임 후 누계 · 전월 대비**입니다.

실적표에 들어가는 것:

| 구분 | 항목 |
|---|---|
| 판매 | 판매량 (통코일 / 슬리팅 / 레벨링 / 블랭킹), 가공 판매 비중 |
| 고객군별 | J사·E사·C사·P사·H사 판매량과 비중 |
| 손익 (천달러) | 매출액, 영업이익, 순이익, 톤당 영업이익 |
| 설비 | 설비별 가동률 |
| 재고·재원 | 창고 현물(가공제품 따로), 해상 미착, 본사 생산 중, 재고량·**재고율**, 재원량·**재원율**, 장기재고 |
| 순운전자본 (천달러) | 매출채권(지연채권 따로), 재고자산, 매입채무, **순운전자본** |
| 차입 (천달러) | 현금, 차입금, 은행 한도, 남은 여력, **한도 소진율**, 이자비용, 자기자본 |

- **재고량** = 창고 현물 + 해상 미착, **재고율** = 재고량 ÷ 앞으로 3개월 월평균 소재 소요량
- **재원량** = 재고량 + 본사 생산 중, **재원율** = 재원량 ÷ 앞으로 3개월 월평균 소재 소요량 (같은 분모를 온 화면이 씁니다)
- **순운전자본** = 매출채권 + 재고자산 − 매입채무. 이 돈을 은행에서 빌려 댑니다
- **은행 한도** = 재고·매출채권의 70% + 토지·건물 장부가의 60% + 본사 지급보증(자본금 60% + 신뢰도 연동)
- 표준 방침에서 창고 현물 2~2.5개월, 해상 미착 1개월, 본사 생산 중 1개월 — 재고율 3개월, 재원율 4개월 안팎입니다
- 자동차강판 리드타임은 제조 1개월 + 해송 1개월 = 2개월입니다. 내시를 석 달 앞까지 줘서 본사 압연 스케줄에 미리 걸어두기 때문입니다
- 은행은 넉 달 넘은 재고를 담보로 안 쳐줍니다. 묵은 재고를 깔고 앉으면 한도부터 줄어듭니다

가공제품은 열흘치쯤 안전재고로 들고 갑니다. 고객 라인은 JIT로 돌고 우리 라인이 매일 그 순서대로 돌 수는 없으니까요.

## 사람들 — 같은 사실도 사람마다 다르게 말한다

누가 하는 말인지에 따라 그대로 믿을지 반쯤 깎아들을지가 달라집니다.

| | 맡은 일 | 말투 |
|---|---|---|
| 정 부장 · 영업 | 고객 영업과 **소재 발주**. 내시를 보고 본사에 소재를 건다 | 자신만만하고 밀어붙인다. 낙관이 섞여 있다 |
| 서 대리 · 구매 | 비품·포장재·**MRO 자재**. 예비품이 없으면 고장 때 더 오래 서고, 포장재가 싸구려면 클레임이 온다 | 과하게 공손하고 조심스럽다. 대신 거짓말을 안 한다 |
| 구 공장장 · 생산 | 라인, 정비, 현장 | 경상도 사투리. 기계 이야기는 틀린 적이 없다 |
| 한 부장 · 관리 | 재무에 **인사·총무**까지. 임금협상, 성과급, 근로감독, 보험, 세무조사, 사택, 채용 | 건조하고 시니컬하다. 결론부터 말하고 위로는 안 한다 |
| 오 과장 · 품질 | 품질 추세, 클레임 | 깐깐하다. 감정 없이 수치로만 말한다 |
| 린 매니저 · 현지 | 현지 직원, 분위기 | 밝고 사람 중심이다. 한국어가 조금 서툴다 |

## 매 턴 하는 일
1. **공장 화면에서 보고를 읽습니다.** 지난달 경영현황, 돌아온 청구서, 아직 안 온 청구서,
   지난 결재의 영향, 경고, 부서 보고가 올라와 있습니다. 여기서는 아무것도 결정하지 않습니다.
2. **결재 시작** — 그 달의 안건이 한 건씩 올라옵니다. 선택지마다 뭘 얻고 잃는지 미리 붙어 있습니다.
3. **소재 발주** — 마지막 안건은 항상 이것입니다. 고객군마다 월 사용량·창고 현물·해상 미착·
   본사 생산 중·재고율·재원율을 한 줄로 보고, **몇 톤을 걸지 직접 적습니다**.
   권장량이 채워져 있지만 그대로 갈 이유는 없습니다.
   걸면 2개월 뒤에 들어오고, 한 달에 소요량의 1.6배까지만 걸립니다.
4. 발주를 확정하면 그대로 한 달(속성은 석 달)이 갑니다.

슬리팅 폭 배분은 결재에서 뺐습니다. 선택지마다 수율이 이미 적혀 있어서
제일 높은 걸 고르는 것 말고는 답이 없었습니다. 정답을 보여주고 정답을 고르게 하는 건 결정이 아닙니다.

**구매 방침을 따로 묻지 않습니다.** 사장이 매 결재마다 고객군별 발주 톤수를 직접 적는 것이 곧 구매 방침입니다.
그래 놓고 "재고를 얼마나 들고 갈까요"를 또 물으면 같은 결정을 두 번 시키는 것이고, 둘이 어긋나면 앞뒤가 안 맞습니다.
본사 소재값 소문은 결정이 아니라 정보로 취급해서 부서 보고와 발주 화면 위에만 띄웁니다.

### 결정에는 주기가 있습니다

| 결정 | 주기 | 화면 |
|---|---|---|
| 소재 발주 (고객군별 톤수) | 매 결재 (노멀 매월 / 속성 매 분기) | 숫자 입력 표 |
| 영업 자원 배분 (100점) | **반기 1회** — 1월·7월 | 숫자 입력 표 |
| 단가 협상 — 자동차·부품사 | **반기 1회** (고객군별로 달이 다름) | 선택지 |
| 단가 협상 — 가전·강건재 | **분기 1회** | 선택지 |
| 전면 정비 | 결정 후 6개월간 다시 묻지 않음 (부분 정비는 3개월, 연기는 2개월) | 선택지 |

**영업 자원 배분**은 인력·출장비·기술지원을 합친 100점을 고객군에 나누는 일입니다.
한 점도 못 받은 고객군은 매달 조금씩 빠지고, 받은 곳은 조금씩 늡니다. 원래 잘 크는 고객군이 더 빨리 큽니다.

### 집중 프로젝트 — 사장이 직접 거는 것

안건은 회사가 올려주는 것이고, 프로젝트는 사장이 겁니다. 분기에 하나, 목표를 숫자로 겁니다.

| | 기간 | 대가 | 목표 |
|---|---|---|---|
| 신규 고객 개척 | 6개월 | 예산 $180k | 시장 점유율 +9% |
| 품질·납기 개선 | 6개월 | 예산 $120k · 진행 중 캐파 −3% | 품질 지수 +6 |
| 채권 회수·재고 정상화 | 3개월 | 예산 $60k · 고객 관계 −3 | 순운전자본 −12% |

셋 다 내놓는 게 다릅니다 — 영업은 돈, 품질은 이번 분기 캐파, 재무는 고객 관계.
그래서 매 분기 같은 게 정답이 되지 않습니다. 방금 한 것은 추천 점수가 깎입니다.

기존 시스템에 얹었습니다. 영업은 `effortQueue`와 점유율, 품질은 품질 지수,
재무는 매출채권과 재고를 그대로 씁니다. 비슷한 걸 새로 만들지 않았습니다.

매달 진척이 메인 화면에 뜹니다 — 몇 %인지, 몇 달 남았는지, **경과 대비 따라가고 있는지**.
끝나는 달에 100% 이상이면 성공, 55% 이상이면 부분 달성, 그 아래는 미달입니다.
프로젝트가 매달 목표 쪽으로 밀어주지만 그것만으로는 모자랍니다 —
품질 프로젝트 중에 라인을 90% 넘게 돌리면 목표치 자체가 안 올라가고,
재무 프로젝트 중에 재고를 쌓으면 채권을 걷어도 순운전자본이 안 줄어듭니다.

### 이정표

첫 흑자, 누계 흑자 전환, 재고 정상화, 납기 석 달 연속 완납, 품질 우수 진입,
태양광 가동, 설비 증설 가동, 1년 무고장, 본사 신뢰 80, 첫 프로젝트 성공.
달성한 분기 결산에서 담당 직원이 한마디 하고 **다음 목표**를 같이 알려줍니다.
보너스를 주는 장치가 아니라, 내 선택이 지표를 움직였다는 걸 그 자리에서 이름 붙여주는 장치입니다.

### 고객군은 성격이 다릅니다

| | 물량 성장 | 협상 | 안 받아주면 | 내시 변동 |
|---|---|---|---|---|
| J사 일본계 자동차 | 느림 | 순함 | −8% | 거의 없음 |
| E사 미주·구주 자동차 | 보통 | 보통 | −20% | 보통 |
| **C사 중국 전기차** | **제일 빠름** | **제일 셈 (+$2/t 더 부름)** | **−38%** | **제일 큼** |
| P사 자동차 부품사 | 보통 | 보통 | −16% | 보통 |
| H사 가전·강건재 | 보통 | 분기마다 | −28% | 큼 |

중국 전기차는 망하는 고객이 아니라 **크는 만큼 어려운** 고객입니다.
물량은 제일 빨리 붇는데, 반기마다 단가를 세게 부르고 안 받아주면 늘려놓은 물량이 그대로 빠집니다.
게다가 모델 주기가 짧아 모델별 내시가 들쭉날쭉하고, 그 물량 보고 들여온 소재가 장기재고로 남아
열화·저가법 평가손·반값 처분으로 돌아옵니다. 여기에 붙으려면 그 셋을 감당할 준비가 있어야 합니다.
바꾼 배분은 3개월 뒤부터 숫자에 나타납니다.

### 단가는 세 층으로 움직입니다

영구히 마진을 깎는 계약은 이 회사에 없습니다. 실무에서도 그런 건 없으니까요.

| | 언제 바뀌나 | 언제 끝나나 | 누가 만드나 |
|---|---|---|---|
| **계약 단가** | 정기 단가 협상에서만 | 다음 정기 협상까지 | 협상 카드 |
| **한시 인하** | 급한 불을 끌 때 | **기한이 되면 자동 원복** (넉 달·여섯 달) | 이탈 방지 · 본사 물량 만회 |
| **약속** | 지금 물량을 받고 값은 나중에 | 다음 정기 협상에서 청구서로 | 대량 수주 · 이탈 방지 |

고객 패널에 `−$7/t × 4,727t = 월 이익 −$33k` 처럼 곱셈을 그대로 적고, 그중 한시분이 있으면
`한시 $5 포함 · 10월 원복`을, 약속이 걸려 있으면 `다음 협상 −$3 약속`을 함께 붙입니다.
한 고객에 총 $12/t를 넘는 양보는 계약이든 한시든 본사가 승인하지 않습니다 —
가공마진 자체가 톤당 $40이라 그 선을 넘으면 팔수록 손해입니다.

약속을 해놓고 협상 날 뒤집을 수는 있습니다. 관계가 무너지고 물량이 크게 빠질 뿐입니다.

**단가 협상**은 깎이러 가는 자리가 아닙니다. 경쟁사가 실제로 견적을 넣었는지, 그 고객이 크는 중인지
쪼그라드는 중인지, 소재 시세가 어디로 가는지 — 정 부장이 들고 오는 정보가 그대로 선택지의 결과를 정합니다.
시황이 받쳐주면 **인상을 요구**할 수 있고, 그게 깎아준 단가를 되돌릴 수 있는 유일한 자리입니다.
쪼그라드는 고객에게 단가를 내주면 물량은 안 오고 깎인 단가만 남습니다.

**유통향 스팟**은 이 게임에서 유일하게 즉시 판가름 나는 판입니다. 받아서 다 팔면 이익과 본사 신뢰가 붙고,
못 팔면 그만큼이 야드에 쌓여 넉 달 뒤 반값에 나갑니다. 완판 확률은 시황이 정하고, 화면에 적혀 있습니다.

## 이 게임의 약속 — 과거의 결정이 미래의 문제를 만든다

**안건은 고정된 카드 더미에서 뽑지 않습니다.** 회사 상태와 지난 결정들이 그 달의 안건을 만듭니다.
정비를 미뤘으면 고장이, 가격을 깎아줬으면 또 깎아달라는 요구가, 재고를 쌓았으면 현금난이 올라옵니다.
조용한 달에는 안건이 한두 건이고, 사고가 겹친 달에는 네 건입니다. 같은 주제는 한 달에 한 번만 묻습니다.

**플레이어에게 보이지 않는 숫자가 있습니다.** 설비 상태, 품질, 현장 피로, 고객사별 관계와 양보 기억,
경쟁사 공격성, 본사 가격 방향. 이 값들은 매달 서로를 움직입니다.

```
물량을 받는다 → 가동률 ↑ → 설비가 닳고 현장이 지친다 → 품질 ↓ → 클레임
→ 그 고객 관계 ↓ → 경쟁사가 파고든다 → 물량이 빠진다
```

플레이어는 이 숫자를 직접 보지 못하고 **부장들의 보고**로 짐작합니다. 보고에는
**확인·추정·소문**이 섞여 있고, 소문은 틀릴 수 있습니다.

**사건이 터질 때는 원인을 짚습니다.** 게임은 모든 결정을 기억합니다.

> 1호 라인이 섰습니다. 두 달 전 정비 연기 이후로 무리하게 돌렸습니다. 최근 넉 달 중 4달을 가동률 90% 넘게 돌렸습니다.

> 납기를 못 맞췄습니다. J사와 P사가 불만을 표시했습니다. 원인 · 석 달 전 하락 소문에 발주 축소

**결재 다음 달에는 그 결정이 무엇을 움직였는지 보여줍니다.**

> J사 대량 수주 — 판매량 +1,200t · 가동률 +4%p · J사 단가 −$12/t · 월 이익 −$45k · ⚠ 2~4개월 뒤 설비·품질 부담

## 정답 스타일은 없습니다
한쪽으로만 밀어붙이는 자동 플레이 여섯 판씩입니다 (노멀, 부임 인수 시작).

|---|---|---|---|
| 공격적 성장 (전부 수락·정비 전부 연기) | 0/6 | $37.8M | 고장 5번, 양보 22번, 자기자본 소진 |
| 현금 지키기 | 4/6 | $33.1M | 고장 6번 — 아낄 데가 아닌 데를 아꼈다 |
| 생산효율 | 1/6 | $47.6M | 정비에 다 쓰고 운전자금이 말랐다 |

한쪽으로만 가면 거의 다 무너집니다. 규율 있게 — 단가를 지키고, 재고를 깔고 앉지 않고,
정비를 제때 하는 — 플레이는 열 판 중 노멀 10판, 하드 9판을 완주했습니다.
그렇게 해도 하드는 끝났을 때 자기자본이 $3M 남짓입니다. 살아남는 것 자체가 성적입니다.

끝나면 점수 대신 **"당신이 만든 회사"**를 서술로 보여줍니다. 어떤 스타일이었는지, 그래서 무엇을
얻고 무엇을 치렀는지, 다음 판에는 무엇을 반대로 해보면 좋을지.

| `world.js` | 숨은 변수(설비·품질·관계·피로)와 인과, 기억, 부서 보고, 경고, 최종 평가 |
| `issues.js` | 회사 상태에서 그 달의 안건을 만든다 |
| `decks.js` | 외부 충격과 사내 이야기 카드 |
| `ui.js` | 화면 |
| `save.js` | 중간 저장 · 명예의 전당 · 앱 설치 |
| `shell.html` | 스타일 |
| `art/` | 512px 픽셀 스프라이트 17장 + 인물 초상 6장. 알파 여백을 잘라낸 원본 |
| `assets.js` | 그 23장을 data URI로 박아둔 것. `make-assets.ps1`이 `art/`에서 만듭니다 |
| `build.sh` | 위 파일들을 `index.html` 하나로 묶기 |
| `manifest.webmanifest`, `sw.js`, `icon-*.png` | 휴대폰에 앱으로 깔리게 하는 것들 |
| `art-prompts.md` | 이미지 생성 프롬프트 |

이 표의 `assets.js`, `build.sh`, 루트 `index.html`은 원본 단일 파일 버전입니다.
현재 전략 게임은 `npm run build`로 생성한 `dist/` 전체를 배포하며, 그림을 바꾸면 이 빌드를 다시 실행합니다.
