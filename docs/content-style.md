# 코일센터의 제왕 — 문구 기준

2026-10-18. 이 문서는 게임 문구를 쓰고 검토할 때 따르는 표현 기준이다. 용어·단위·기간·사실성·직원 말투를 정의하며, 계산·확률·저장·판정 우선순위는 바꾸지 않는다.

## 한 문장에 무엇을 담는가

먼저 지금 일어난 일을 말한다. 다음으로 돈·수량과 적용 기간을 말한다. 마지막으로 플레이어가 확인할 장부나 다음 행동을 붙인다. 직원의 농담과 말투는 그 뒤에 남긴다. 예: “설치비 $520,000을 지급했어요. 이번 결산부터 매달 고정비가 $9,000 줄어요. 경영 장부에서 확인해 주세요.”

화면 문구를 쉽게 만들기 위해 정확한 뜻을 버리지 않는다. ‘좋아짐’, ‘효과 상승’, ‘재무 감당’, ‘물량 ↑’만으로 끝내지 않는다. 무엇이, 언제, 어떤 조건에서 달라지는지 적는다. 계산 근거가 없으면 숫자나 기간을 새로 만들지 않는다. 공장·직원·명령을 중심에 두고, 설명을 별도 경영 대시보드로 늘리지 않는다.

| --- | --- | --- |

| 순이익 | 영업이익에서 이자와 못 받은 대금 손실을 뺀 금액. 이 게임 계산의 정의다. | `R.np = op - interest - badDebt` |
| 모법이익 | 본사 소재 이익 + 코일센터 영업이익. 목표명은 유지하고 항상 풀이를 제공한다. | `R.consolidated`, `s.hq.cumConsolidated` |
| 자기자본 | 출자받은 자본금에 누적 순이익을 반영한 장부 금액. 쓸 수 있는 현금이 아니다. | `s.equity += np`; 초기값 `createInitialState` |
| 자본금 | 설립 때 출자받은 금액. 현재 자기자본과 구분한다. | `s.paidIn` |
| 창고 재고 | 현재 창고에 있는 소재와 가공 제품. 톤으로 표시한다. | `inventoryTons(s)` |
| 도착 예정 물량 | 아직 창고에 오지 않은 발주. ‘해상 미착’은 **운송 중 소재**, ‘본사 생산 중’은 **본사에서 준비 중인 소재**로 풀이한다. | `s.poOpen`; `seaTons`/`prodTons`의 현재 경계 |
| 재고량 | 창고 재고 + 운송 중 소재. ‘창고 재고’와 혼용하지 않는다. | `stockNow(s).inv`, `stockOf(R).inv` |

| 확보한 전체 물량 | 재고량 + 본사 생산 중 물량. 기존 ‘재원량’의 풀이. ‘재원율’은 이 물량의 개월 수다. | `stockNow(s).res/resM`, `stockOf(R)` |
| 외상매출금(매출채권) | 이미 팔았지만 고객에게 아직 받지 못한 돈. 이후 표에서는 ‘받을 고객 대금’도 허용한다. | `s.ar[].amount` |
| 지급 예정 대금(매입채무) | 입고한 소재 중 본사에 아직 내지 않은 돈. 현금 차감은 지급 예정월에 한다. | `s.ap`, STEP 4/16 |

| 가동률 | 결산: 실제 투입 소재 ÷ 명목 가공 가능량. 결재 전 라인 그림: 주문 기준 부하. 두 비율을 같은 실적으로 말하지 않는다. | `R.util`, `lineUtilOf`; `ui.js lineList` |
| 가공 가능량 | 기존 ‘캐파’. 월별 가공할 수 있는 양. 주문량·납품량과 다르다. | `capacityOf`, `worldPre`, `mods.capMult` |
| 톤당 영업이익 | 기간 영업이익 ÷ 기간 판매량. ‘마진’이 이 뜻일 때 정확히 쓴다. | `perfPanel`, `companyProfile.m.margin` |
| 가공 마진 / 가격 할인 | 가격 산정에 쓰는 톤당 가공 마진, 고객에게 깎아 준 톤당 금액. 둘 다 최종 영업이익이나 순이익이 아니다. | `CFG.PROC_MARGIN`, `W.cut`, `cutNow`, `unitPrice` |
| 순운전자본 | 받을 고객 대금 + 창고 재고의 장부 금액 − 지급 예정 매입 대금. 계산상 운송 중 금액은 제외된다. 그 전액을 반드시 은행에서 빌린다는 뜻은 아니다. | `nwcOf`, `R.bs.nwc` |
| 남은 대출 한도 | 현재 한도 − 차입금. 사용할 수 있는 금액은 0 이상으로 표시하되 초과액은 따로 밝힌다. | `s.debt.limit/principal`, `creditLimit` |
| 자금 여력(추정) | 현금 + 남은 대출 한도를 현재 월 소재 필요액의 85% + 기본 고정비로 나눈 참고값. 수금·만기·모든 추가비용을 반영한 현금흐름 예측이 아니다. | `runway` |
| 확정 내시 | 고객이 미리 알려 준 제품 주문 예정량. 현재 수요 원장에 고정된 값이지, 실제 납품 보장량은 아니다. 고객별 분할은 현재 구성비에 따른 배분값이다. | `s.nasi`, `ccCustomersDossier`, `makeNasi` |
| 양품률 / 품질 지수 | 화면 양품률은 품질 지수를 환산한 상태값이다. 특정 로트의 실제 검사 통계로 확대하지 않는다. 지수 +6점과 양품률 +6%p는 다르다. | `qualityPct(q) = 94 + q*0.05` |

금액은 `$26,000`, 수량은 `1,200톤`, 단가는 `톤당 $4`, 월비용은 `매달 $9,000`으로 쓴다. 표가 천 달러 단위면 제목에 `단위: 천 달러`를 적고 중복된 `$…k`를 피한다. 좁은 곳의 k/M은 단위 설명과 전체 금액을 함께 제공할 때만 쓴다. 1k=1,000달러, 1M=1,000,000달러다. 비용과 이익은 `현금 −$26,000`, `영업이익 +$10,000`처럼 지표 이름을 앞에 붙인다. 방향을 색만으로 표시하지 않는다.

비율은 `%`, 비율의 차이는 `%p`, 지수 변화는 `점`이다. 상대 9% 증가는 1.09배이며 9%p가 아니다. `Math.min/max`, 정수 반올림, 0~100 제한을 거친 적용값과 요청값을 구분한다. ‘+8’ 요청이 상한에서 ‘+2’만 반영됐으면 +8을 실제 증가로 보고하지 않는다. 새 계산을 추가하지 않고 기존 전후 값·처리 결과를 읽는다.

## 기간과 확실성

| 분류 | 화면 표시 | 허용되는 근거 / 금지하는 단정 |
| --- | --- | --- |
| 확인된 사실 | `확인` | 현재 상태, 완료 원장, 실제 실행 분기. 앞으로 생길 사건을 확정형으로 쓰지 않는다. |
| 직접 적용 | `이번 결재 적용` 또는 `이번 결산 적용` | 실행문이 바꾼 값. `lever`에 적은 의도값이 실제 전후 차이인지 먼저 확인한다. |
| 관측 상태 | `현재 상태` / `이번 기간 말 상태` | 여러 결재와 월 계산이 합쳐진 결과. 하나의 결재 효과로 귀속하지 않는다. |
| 추정 | `추정` + 기준 | 계산식·전제·단위·기간을 가까이 쓴다. `settleImpacts` 판매량/가동률/단가×수량은 별도 추정이다. |
| 관련 기록 | `관련 결정 기록` + 기록 날짜 | `causeRef`는 최근 8개월의 태그가 맞는 기록 하나를 찾는다. 원인 비중·인과 증명이 아니다. 화살표도 시간 순서로만 설명한다. |
| 소문 | `소문` + 전달자 | 직원이 전해 들은 정보. 확인되지 않았고 틀릴 수 있다. 미래 난수를 미리 확인된 사실로 내보이지 않는다. |

수치가 섞인 행 전체를 ‘추정’으로 묶지 않는다. 현금 지급은 직접 적용, 월말 관계는 상태, 판매량 기여는 추정일 수 있다. `im.cash`, `im.cut`, `im.rel`도 각각 핸들러와 제한값을 확인한다. `im.vol`은 실제 판매 증가율이 아니라 수요 기반 변경을 요약한 값이다. `im.risk`에는 미래 위험뿐 아니라 이미 적용된 월비용·완료한 행동이 섞여 있으므로 전부 ‘아직 안 온 청구서’로 부르지 않는다.

월 모드는 한 달, 분기 모드는 세 달을 월별로 집행한다. 손익·수량은 해당 기간 합계, 재고·현금·채권·차입은 기간 말 잔액이다. 조기 종료로 두 달만 집행했으면 ‘이번 2개월’로 표시한다. 합친 보고서의 추정 금액에 ‘월 이익’을 붙이지 않는다. 이정표는 발생한 실제 월을 적는다. 상태 `s.turn`은 다음 월을 가리킬 수 있으므로 완료 원장 `R.turn/R.date`와 혼동하지 않는다.

설비 가동은 `readyTurn`, 채권·채무는 `dueTurn`, 집중 과제 평가는 `project.end`, 한시 할인 복귀는 `temp.until`을 표시한다. ‘6개월’로 공통 고정하지 않는다. 진행률은 지금 목표에 얼마나 가까운지 보여주며 최종 성공 보장이 아니다. 종료 시점에 판정되지 않은 과제는 ‘미완료 · 평가 예정’이다. 임기 후 예정일을 숨기거나 기간을 줄이거나 환불하지 않는다. end48/49/50/52 경계는 T13의 실제 실행 결과를 기준으로 연결한다.

태양광은 현재 규칙상 결재 즉시 설치비가 차감되고 `extraFixed`가 바뀌어 이어지는 월 결산부터 절감된다. 설치 큐·3개월 지연이 없다. ‘3개월 걸렸고 지난달 고지서가 줄었다’는 문구는 사용하지 않는다. 절감은 현금 보너스 입금이 아니라 고정비 감소다. 20년 계약·지붕 증축 금지는 코드가 실제 제약으로 검사하지 않으므로 현재 게임 효과로 단정하지 않는다.

## 여섯 직원의 말투

| 인물 | 유지할 특징 | 기본보고와 후속 행동 |
| --- | --- | --- |
| 정 부장 | 짧고 자신만만하다. 권유에는 열의를 담되 확인과 소문을 구별한다. | 이번 달 확정 내시와 고객별 **배분 추정** → 거래처와 수주 |
| 서 대리 | 공손하고 조심스럽다. 숫자와 적용 시점은 흐리지 않는다. | 재고 개월 수의 범위 → 소재와 물류 |
| 구 공장장 | 짧은 사투리. “입니더/보이소”를 유지한다. | 설비 상태·정비 경과 → 생산 현황 |
| 한 부장 | 결론·금액·시점, 건조한 농담. 현금과 손익을 특히 엄격히 나눈다. | 현금·차입·수금/지급 예정 → 경영 장부 |
| 오 과장 | 원칙과 수치를 말한다. 측정하지 않은 로트나 지속 기간을 꾸미지 않는다. | 품질 지수 환산 상태와 확인할 자료 → 사내 보고/생산 현황 |
| 린 매니저 | 부드럽고 사람 중심. 불만·퇴사 가능성과 확정 퇴사를 구별한다. | 현장 피로·사기 점수 → 사내 보고 |

직원 이름·역할·보고 구분을 모바일에서도 보존한다. 보고에 해당 항목이 없으면 “아직 이 항목의 기록이 없습니다”라고 말하고 돌아갈 명령을 제공한다. 경고가 없다는 뜻을 “안전합니다”, “아무 문제 없습니다”로 넓히지 않는다.

## 결과·경고·결말

결재 직후에는 선택 내용과 바로 적용한 값, 다음 적용 시점을 말한다. 결과 대사 속 하루·사흘은 월 경과를 실제로 실행했다는 뜻으로 읽히면 안 된다. 일정 데이터가 없는 대화·방문 묘사는 배경 이야기로만 유지한다. 인원 수·고객 수·일수·추가 수익을 게임 실적으로 표시하려면 상태나 원장 근거가 필요하다.

경고는 현재 징후 → 가능한 위험 → 확인할 장부 순서로 쓴다. 재고가 1.3개월치라고 “두 달 뒤 결품”, 관계가 낮다고 “이미 이탈 중”으로 단정하지 않는다. 수금 잔액 건수는 연체 건수가 아니다. 품질 수치 두 시점 비교는 ‘3개월 연속 하락’이 아니다.

퇴임은 `COMPLETE`(임기 완료), `INSOLVENT`(현금 부족으로 종료), `CAPITAL_ERODED`(자기자본 소진으로 종료)를 구분한다. 실제 `overReason`과 기존 `grade()`의 우선순위를 그대로 읽고 새 판정을 만들지 않는다. 누적 영업이익 0은 적자가 아니다. 평균 양품률이 높았다고 ‘끝까지 좋았다’, 최종 비중이 높다고 ‘마지막 해 내내 그랬다’, 선택 점수가 높다고 ‘그 선택 덕분에 흑자’라고 쓰지 않는다.

마지막 화면은 ‘재임 N개월의 기록’으로 시작한다. 이익·실제 상태·선택 성향을 따로 소개한다. 고객 수·정비 횟수 등 기록이 없으면 추가하지 않는다. 미완료 과제는 예상 평가월과 현재 진척을 인수인계하고 실패라고 부르지 않는다. 다시 하기와 기록 내려받기는 유지한다.

## 적용 책임과 완료 기준

- T12는 `src/ui/company.js`와 `src/ui/dossiers.js`만 편집한다. 여섯 기본보고, 장부 명칭·풀이·빈 상태·보고 복귀 명령을 맡는다. `engine.js` 재고 연령 라벨의 겹치는 경계는 dossiers의 표시·풀이로 보완하고 엔진을 편집하지 않는다. 장부를 읽는 행위가 월 계산이나 난수를 실행하지 않게 유지한다.
- T13은 `world.js`, `issues.js`, `ui.js`의 결과·관련 기록·직접/추정/상태 행, 조건부 직원보고, 원본 장부 문구, 태양광, 3/6개월 과제, 연차·종료 이유 해석을 맡는다. 부모 작업자가 추가 승인한 `engine.js`·`decks.js`의 좁은 문자열 교정도 T13 담당이다. 수치·난수·일정·판정은 그대로 둔다.
- T18은 새 회고 어댑터에서 실제 기록·종료 이유·빈 상태·미완료 과제를 표현한다. 원본 `grade/companyProfile/renderEnd` 문구 교정은 T13과 계약을 공유하며 같은 파일을 동시에 편집하지 않는다. 기존 등급을 재해석해서 바꾸지 않는다.
- T24: 목록의 모든 표면군을 실제 화면에서 확인한다. 정상/빈 이력/상한 값/월·분기/조기 종료/임기 뒤 과제와 실제 처리의 금액·시점·조건이 맞아야 한다. 문자열을 그대로 복제한 테스트로 검증을 대신하지 않는다.

문구 작업에서 계산 변경이 필요해 보이면 문구를 현재 규칙에 맞게 줄이고 차이를 기록한다. 경제 계산을 조용히 고쳐 표현을 사실로 만들지 않는다.

이 파일 소유권 안내는 2026-10-18 부모 작업자의 인계 지시를 반영한다. 확정 계획 자체를 다시 쓰지 않는다. 문구 목록의 T12/T13/T18 표시는 이 소유권 규칙에 따라 적용하며, T12와 T13은 문서의 표시 문구·대상 계약을 공유한다.
